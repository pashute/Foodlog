# Issues report instructions:

- Dated ## section with report header starting with keyword reportname and date. 
- Subsections ### with report key and headline. 

- Terse report, remove unnecessary words. 
- Line by line per issue and sub-issue
- Headline style - with minimal details, enough to understand and fix.  
- Section header - with report type:  Problem:, Fixed:, Skipped (can't  do):, Skipped: (intentionally), etc. 
- Filename only (with extension). Multiple indented files under parent 
- Do not delete or overwrite old reports 
- Unless instructed otherwise append to end of report in new section. 
- Never touch the issues.md three-line header (filename, version, read instructions directive), except in a code-wide version number update.
